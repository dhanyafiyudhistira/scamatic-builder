# Product Specification — SCADA SVG Interactive Elements

> Generated from `flows_alif.json` (Node-RED → ThingsBoard MQTT bridge)
> Target: SCADA SVG HMI with React/Vite frontend bound to ThingsBoard telemetry & RPC

---

## 1. System Overview

This document defines the interactive SVG attribute contract for the SCADA frontend, derived from the Node-RED flow that bridges the HMI to ThingsBoard.

**Data path:**

```
SVG Toggle (user click)
   → RPC call (method: setXxxx, params: bool)
   → MQTT topic v1/devices/me/rpc/request/+
   → Node-RED "Handle Boolean RPC"
   → MQTT topic v1/devices/me/telemetry
   → ThingsBoard timeseries
   → WebSocket subscription
   → SVG lamp indicator + value span updates
```

**MQTT Broker:** `demo.thingsboard.io:1883` (plain MQTT, protocol v4, clean session)
**Telemetry topic (publish):** `v1/devices/me/telemetry`
**RPC topic (subscribe):** `v1/devices/me/rpc/request/+`
**Telemetry refresh:** Analog sensors generated every **10 seconds** by `inject_sensor_tb` node.

## 3. SVG Element Attribute Contract

To make the SVG interactive and bindable from React, each SCADA element must carry standardized `data-*` attributes. The frontend selects elements by these attributes and attaches event listeners or pushes telemetry-driven state.

### 3.1 Toggle Switch — Boolean Control

Each clickable valve/motor element in the SVG.

**Required attributes:**

| Attribute            | Required | Example          | Purpose                                                       |
| -------------------- | -------- | ---------------- | ------------------------------------------------------------- |
| `id`                 | ✅       | `svg-V106`       | Unique DOM id; convention: `svg-{TAG}`                        |
| `data-scada-type`    | ✅       | `toggle`         | Element role: `toggle` \| `lamp` \| `value`                   |
| `data-tag`           | ✅       | `V106`           | Logical tag — must match telemetry key                        |
| `data-rpc-method`    | ✅       | `setV106`        | ThingsBoard RPC method to invoke on click                     |
| `data-state`         | ✅       | `false`          | Current bound state — toggled by React on telemetry update    |
| `data-on-color`      | ⚠️       | `#22c55e`        | Optional override; default green                              |
| `data-off-color`     | ⚠️       | `#475569`        | Optional override; default slate                              |
| `cursor`             | ✅       | `pointer` (CSS)  | Make it visibly clickable                                     |

**Example:**
```xml
<g
  id="svg-V106"
  data-scada-type="toggle"
  data-tag="V106"
  data-rpc-method="setV106"
  data-state="false"
  data-on-color="#22c55e"
  data-off-color="#475569"
  style="cursor: pointer;"
>
  <rect width="40" height="40" fill="currentColor" />
  <text x="20" y="55" text-anchor="middle">V106</text>
</g>
```

### 3.2 Lamp Indicator — Boolean Read-only

Visual indicator that mirrors the toggle state (can be a separate SVG circle or the toggle body itself).

**Required attributes:**

| Attribute            | Required | Example     | Purpose                                          |
| -------------------- | -------- | ----------- | ------------------------------------------------ |
| `id`                 | ✅       | `lamp-V106` | Unique DOM id; convention: `lamp-{TAG}`          |
| `data-scada-type`    | ✅       | `lamp`      | Identifies as read-only lamp                     |
| `data-tag`           | ✅       | `V106`      | Bound telemetry key                              |
| `data-state`         | ✅       | `false`     | Current state — updated by React                 |
| `data-on-fill`       | ⚠️       | `#22c55e`   | Color when state = true                          |
| `data-off-fill`      | ⚠️       | `#1e293b`   | Color when state = false                         |
| `data-on-glow`       | ⚠️       | `true`      | Apply CSS filter `drop-shadow` when on           |

**Example:**
```xml
<circle
  id="lamp-V106"
  data-scada-type="lamp"
  data-tag="V106"
  data-state="false"
  data-on-fill="#22c55e"
  data-off-fill="#1e293b"
  data-on-glow="true"
  cx="100" cy="100" r="8"
  fill="#1e293b"
/>
```

### 3.3 Value Span — Analog Read-only

Numeric display for analog telemetry (LSH202, LSL203, LT301).

**Required attributes:**

| Attribute            | Required | Example      | Purpose                                          |
| -------------------- | -------- | ------------ | ------------------------------------------------ |
| `id`                 | ✅       | `val-LSH202` | Unique DOM id; convention: `val-{TAG}`           |
| `data-scada-type`    | ✅       | `value`      | Identifies as analog display                     |

  data-tag="LSH202"
  data-unit="%"
  data-decimals="2"
  data-min="0"
  data-max="100"
  data-alarm-high="80"
  data-alarm-low="20"
  x="200" y="150"

## 5. React Binding Pattern (Reference Implementation)

```jsx
// useScadaBinding.js
import { useEffect } from 'react';

export function useScadaBinding(svgRef, telemetry, sendRpc) {
  // Bind toggles → RPC on click
  useEffect(() => {
    if (!svgRef.current) return;
    const toggles = svgRef.current.querySelectorAll('[data-scada-type="toggle"]');
    const handlers = [];

    toggles.forEach(el => {
      const tag    = el.dataset.tag;
      const method = el.dataset.rpcMethod;
      const handler = () => {
        const current = el.dataset.state === 'true';
        sendRpc(method, !current);
      };
      el.addEventListener('click', handler);
      handlers.push({ el, handler });
    });

    return () => handlers.forEach(({ el, handler }) =>
      el.removeEventListener('click', handler)
    );
  }, [svgRef, sendRpc]);

  // Apply telemetry → DOM
  useEffect(() => {
    if (!svgRef.current) return;

    Object.entries(telemetry).forEach(([tag, value]) => {
      // Toggles
      svgRef.current.querySelectorAll(`[data-scada-type="toggle"][data-tag="${tag}"]`)
        .forEach(el => {
          el.dataset.state = String(value);
          el.style.color = value
            ? (el.dataset.onColor  || '#22c55e')
            : (el.dataset.offColor || '#475569');
        });

      // Lamps
      svgRef.current.querySelectorAll(`[data-scada-type="lamp"][data-tag="${tag}"]`)
        .forEach(el => {
          el.dataset.state = String(value);
          el.setAttribute('fill', value
            ? (el.dataset.onFill  || '#22c55e')
            : (el.dataset.offFill || '#1e293b'));
          if (el.dataset.onGlow === 'true') {
            el.style.filter = value ? 'drop-shadow(0 0 6px #22c55e)' : 'none';
          }
        });

      // Values
      svgRef.current.querySelectorAll(`[data-scada-type="value"][data-tag="${tag}"]`)
        .forEach(el => {
          const decimals = parseInt(el.dataset.decimals || '2', 10);
          const unit     = el.dataset.unit || '';
          el.textContent = `${Number(value).toFixed(decimals)} ${unit}`;

          // Alarm coloring
          const high = parseFloat(el.dataset.alarmHigh);
          const low  = parseFloat(el.dataset.alarmLow);
          if (!isNaN(high) && value >= high)      el.setAttribute('fill', '#ef4444');
          else if (!isNaN(low) && value <= low)   el.setAttribute('fill', '#f59e0b');
          else                                    el.setAttribute('fill', '#22d3ee');
        });
    });
  }, [svgRef, telemetry]);
}
```

## 6. ThingsBoard WebSocket Subscription

Subscribe to all tags in a single WebSocket frame (ThingsBoard v3.6.2+ requires `cmds` array):

```json
{
  "cmds": [
    {
      "entityType": "DEVICE",
      "entityId": "<DEVICE_UUID>",
      "scope": "LATEST_TELEMETRY",
      "cmdId": 1,
      "type": "TIMESERIES",
      "keys": "V106,V205,V201,V304,M303,LSH202,LSL203,LT301"
    }
  ]
}
```

## 7. RPC Outbound (Send to Device)

REST endpoint:
```
POST {THINGSBOARD_URL}/api/plugins/rpc/oneway/{DEVICE_ID}
Headers: X-Authorization: Bearer {JWT}
Body:
{
  "method": "setV106",
  "params": true
}
```

The Node-RED flow's `func_rpc_tb_new` will catch the RPC and immediately echo the new state back as telemetry, closing the optimistic-update loop.

## 8. Naming Convention Summary

| Element kind | DOM id prefix | `data-scada-type` |
| ------------ | ------------- | ----------------- |
| Toggle       | `svg-`        | `toggle`          |
| Lamp         | `lamp-`       | `lamp`            |
| Value        | `val-`        | `value`           |

All three share `data-tag` as the join key against telemetry payloads.

## 9. Open Questions / Notes

- **Polling vs WebSocket:** Flow publishes telemetry every 10 s; frontend should prefer WebSocket subscription to avoid the latency floor.
- **Optimistic UI:** Consider setting `data-state` immediately on click, then reconciling on telemetry echo to avoid the perceived 10 s lag.
- **Tag namespace:** All tag names (`V###`, `M###`, `LSH###`, `LSL###`, `LT###`) follow ISA-5.1 P&ID conventions — keep this convention when adding new tags.
- **Production sensor source:** `func_sensor_tb` currently uses `Math.random()`. Replace with Modbus/OPC-UA input nodes before deployment.
